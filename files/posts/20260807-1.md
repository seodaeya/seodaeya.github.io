## 💻 깃허브 블로그(github.io), 왜 애드센스 심사에서 계속 거절될까?

개발자나 테크 에디터들이 자신만의 기술 블로그를 구축할 때 가장 선호하는 플랫폼 중 하나는 단연 <strong>GitHub Pages(github.io)</strong>입니다. 무료 호스팅, Markdown 기반 작성, 개발자 친화적인 버전 관리 등 수많은 장점이 있기 때문입니다.

하지만 블로그가 일정 수준 이상 성장하여 <strong>구글 애드센스(Google AdSense) 수익화 심사를 신청하면 '사이트가 작동하지 않음', '가치 있는 콘텐츠 없음', 혹은 원인을 알 수 없는 무한 거절</strong>을 겪는 경우가 매우 많습니다.

"글도 10개 넘게 썼고 코드 설명도 알차게 적었는데 왜 계속 승인이 안 날까?", "호스팅케이알이나 포크번에서 유료 도메인(.com, .kr)을 사서 연결하면 바로 해결될까?" 고민하는 분들을 위해, 본 아티클에서는 <strong>github.io 구조상의 애드센스 거절 원인부터 커스텀 도메인 연동 및 승인 통과 4단계 로드맵</strong>을 완벽히 정리해 드립니다.

---

## 🚨 1. github.io 서브도메인이 애드센스 심사에서 거절되는 3가지 기술적 이유

### 1) 구글 애드센스 정책 변경 (루트 도메인 검증 필수화)
구글 애드센스는 지난 2020년 이후 사이트 검토 정책을 대폭 강화했습니다. 기본적으로 <strong>개인이 직접 소유권을 증명할 수 있는 루트 도메인(예: example.com)</strong> 단위로 사이트를 등록하고 검토하도록 체계가 변경되었습니다.

### 2) 공유 3차 서브도메인(`*.github.io`)의 한계
`username.github.io` 주소는 독립된 1차/2차 도메인이 아니라, GitHub 커뮤니티가 소유한 `github.io` 밑에 붙은 3차 서브도메인입니다. 구글 애드센스 심사 로봇은 사이트 검토 시 DNS 루트 수준의 소유권이나 `ads.txt` 파일 검증을 수행하는데, **github.io 전체의 소유권은 GitHub 회사에 있으므로 개인 사용자가 자신이 사이트의 정당한 소유자임을 기술적으로 증명하기 어렵습니다.**

### 3) '사이트를 찾을 수 없음' 자동 거절 메커니즘
많은 개발자들이 경험하는 '사이트가 다운되었거나 찾을 수 없음' 거절 메커니즘은 실제로 블로그가 다운된 것이 아닙니다. 구글 애드센스 봇이 `github.io` 서브도메인을 검토할 때 루트 도메인 보안 정책에 걸려 **사이트 수집 단계에서 자동 거부(Reject)** 처리를 내리기 때문입니다.

## 🌐 2. 호스팅케이알(HostingKR)에서 도메인을 사면 바로 승인될까?

"그럼 호스팅케이알(HostingKR)이나 가비아(Gabia), 포크번(Porkbun)에서 내 이름으로 된 `.com`이나 `.kr` 도메인을 사서 넣으면 바로 당일 승인이 날까?"라는 질문을 자주 받습니다.

결론부터 말씀드리면, <strong>도메인 구매는 애드센스 심사를 받을 수 있는 '정식 주소(입장권)'를 확보한 것일 뿐, 구매 직후 즉시 광고가 달리는 것은 아닙니다.</strong>

도메인을 구매한 후 반드시 아래 3가지 기술적/콘텐츠 요건을 맞춰야 심사가 진행됩니다:

1. <strong>DNS CNAME/A 레코드 연동:</strong> 구매한 커텀 도메인을 GitHub Pages 레포지토리와 CNAME으로 정상 연결해야 합니다.
2. <strong>HTTPS (SSL 보안 프로토콜) 적용:</strong> 보안 연결이 되지 않은 사이트는 애드센스 심사 대상에서 즉시 제외됩니다. (GitHub Pages는 무료 SSL을 자동 발급해 줍니다.)
3. <strong>구글 애드센스 계정 메타 태그 삽입:</strong> `<meta name="google-adsense-account" content="ca-pub-..." />` 소유권 확인 태그를 HTML `<head>`에 정확히 삽입해야 합니다.

## 🛠️ 3. GitHub Pages 애드센스 승인을 위한 4단계 완벽 로드맵

GitHub Pages 블로그로 구글 애드센스 승인을 한 번에 통과하기 위해 반드시 거쳐야 하는 4단계 실행 절차입니다.

### 1단계: 커스텀 루트 도메인 구매 및 CNAME 연동
* 호스팅케이알 등에서 기억하기 쉬운 `.com` 또는 `.kr` 개인 도메인을 구매합니다.
* GitHub 레포지토리 **Settings ➔ Pages ➔ Custom domain**에 구매한 도메인을 입력합니다.
* DNS 관리 페이지에서 아래 GitHub Pages IP로 A 레코드 4개를 추가하고, `www` CNAME을 `username.github.io`로 지정합니다:
  ```text
  185.199.108.153
  185.199.109.153
  185.199.110.153
  185.199.111.153
  ```

### 2단계: 필수 규정 페이지 구축 (Privacy Policy & About)
구글 애드센스 심사관(봇)이 사이트의 정당성을 평가할 때 <strong>개인정보처리방침(Privacy Policy)</strong> 유무를 매우 엄격하게 봅니다.
* 블로그 하단(Footer)에 `/privacy/` 및 `/about/` 페이지 링크를 추가하세요.
* 쿠키 수집 및 제3자 광고(Google AdSense) 관련 안내 문구를 명시해야 합니다.

### 3단계: 고품질 롱폼 포스팅 15개 이상 확보 (E-E-A-T)
글 3~5개 상태에서 신청하면 '가치 있는 콘텐츠 없음(Thin Content)'으로 100% 거절됩니다.
* 최소 <strong>15\~20개 이상의 독자적인 기술 포스팅</strong>을 작성하세요.
* 단순히 소스 코드만 덩그러니 올리지 말고, **문제 원인과 해결 과정, 12세도 이해할 수 있는 쉬운 설명이 포함된 1,500자 이상의 알찬 글**로 채워야 합니다.
* 빈 카테고리나 글이 1개뿐인 카테고리는 심사 전 미리 정리하거나 제거하세요.

### 4단계: 애드센스 소유권 태그 삽입 및 재신청
사이트의 `<head>` 태그 내부에 구글 애드센스 계정 확인 태그를 추가한 후, 애드센스 콘솔에서 새로 연결한 루트 도메인으로 검토를 신청합니다.

```html
<meta name="google-adsense-account" content="ca-pub-9646087317436086" />
```

## ❓ 4. 자주 묻는 질문 (FAQ)

### Q1. 커스텀 도메인을 연결하면 기존 github.io 주소로 들어오는 방문자는 어떻게 되나요?
GitHub Pages는 기존 `username.github.io`로 들어오는 모든 요청을 새로 설정한 커스텀 도메인(`seodaeya.com`)으로 **301 리다이렉트(자동 이동)**해 주므로 기존 트래픽 손실 걱정을 하지 않으셔도 됩니다.

### Q2. 심사는 얼마나 걸리나요?
도메인을 정상 연결하고 심사를 제출하면 구글 심사팀 및 봇이 검토를 진행하며, 보통 **수일에서 길게는 2~4주** 정도 소요됩니다.

## 📌 5. 총평 및 정리

`github.io` 블로그의 애드센스 거절은 여러분의 글 실력이 부족해서가 아니라, **3차 서브도메인이 가지는 구글 정책상의 한계 때문일 확률이 매우 높습니다.**

독자적인 **커스텀 도메인 연동 ➔ 필수 개인정보처리방침 페이지 구축 ➔ 15개 이상의 알찬 기술 포스팅**의 3박자를 갖추신 후 재신청하신다면 승인 통과의 기쁨을 누리실 수 있을 것입니다!
