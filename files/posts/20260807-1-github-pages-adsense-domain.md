## 💻 깃블로그(github.io), 왜 애드센스 심사에서 계속 거절될까?

개발자나 테크 에디터들이 자신만의 기술 블로그를 구축할 때 가장 선호하는 플랫폼 중 하나는 단연 <strong>GitHub Pages(github.io)</strong>입니다. 무료 호스팅, Markdown 기반 작성, 개발자 친화적인 버전 관리 등 수많은 장점이 있기 때문입니다.

하지만 블로그가 일정 수준 이상 성장하여 <strong>구글 애드센스(Google AdSense) 수익화 심사를 신청하면 '사이트가 작동하지 않음', '가치 있는 콘텐츠 없음', 혹은 원인을 알 수 없는 무한 거절</strong>을 겪는 경우가 매우 많습니다.

"글도 10개 넘게 썼고 코드 설명도 알차게 적었는데 왜 계속 승인이 안 날까?", "유료 도메인(.com, .kr)을 사서 연결하면 바로 해결될까?" 고민하는 분들을 위해, 본 아티클에서는 <strong>거절 사유별 정확한 처방부터 커스텀 도메인 연동, 그리고 필자가 실제로 겪은 '가치 없는 콘텐츠' 거절 극복기</strong>까지 정리해 드립니다.

## 🚨 1. 거절 사유부터 정확히 읽자: 3종류는 처방이 다르다

많은 글이 "github.io라서 안 된다"고 단정하지만, 필자의 실제 경험은 다릅니다. 이 블로그는 <strong>github.io 서브도메인 그대로 사이트 소유권 확인을 통과</strong>했습니다. 막힌 것은 소유권이 아니라 콘텐츠 평가였습니다. 거절 화면을 흘려 넘기지 말고, 아래 3종류 중 어디에 해당하는지 먼저 구분하세요.

| 거절 유형 | 화면 문구 | 진짜 원인 | 처방 |
| :--- | :--- | :--- | :--- |
| <strong>사이트 작동·접근 불가</strong> | 사이트가 작동하지 않음, 찾을 수 없음 | 크롤러 차단, 빌드 깨짐, 잘못된 URL 제출 | <strong>robots.txt, 빌드 결과물, 제출 URL 점검</strong> |
| <strong>가치 없는 콘텐츠</strong> | 가치가 별로 없는 콘텐츠 | 얇은 글, 타인 글 재구성, AI 대량 생성 의심 | <strong>글 보강·noindex 정리·1차 경험 추가 (이 글 3\~5절)</strong> |
| <strong>준비 미비</strong> | 광고 게재가 준비되지 않은 사이트 | 필수 페이지 누락, 트래픽·구조 부족 | <strong>privacy/about 구축, 글 수·내부 링크 정비</strong> |

> 💡 <strong>필자의 실제 판정</strong><br />
> 소유권 확인은 초록 체크(통과), 정책 위반 항목은 <strong>"가치가 별로 없는 콘텐츠"</strong>였습니다. 도메인 문제가 아니었기에 커스텀 도메인을 산다고 해결될 일이 아니었습니다. 여러분도 도메인을 사기 전에 거절 사유 행을 먼저 확인하세요.

## 🌐 2. "커스텀 도메인을 사면 바로 승인될까?"에 대한 정정

"유료 도메인을 사서 넣으면 당일 승인이 날까?"라는 질문을 자주 받습니다. 결론부터 말씀드리면, <strong>도메인 구매는 심사를 받을 수 있는 '정식 주소(입장권)'를 확보한 것일 뿐, 콘텐츠 판정을 통과시켜 주지 않습니다.</strong>

github.io 서브도메인에 대한 오해를 바로잡습니다.

* <strong>소유권 증명은 된다:</strong> HTML 메타 태그(<strong>google-adsense-account</strong>) 방식으로 소유권 확인이 정상 통과됩니다. 이 블로그가 직접 증명했습니다.
* <strong>ads.txt도 동작한다:</strong> <strong>public/ads.txt</strong>에 <strong>google.com, pub-XXXXXXXXXX, DIRECT</strong> 한 줄이면 검증됩니다.
* <strong>커스텀 도메인이 필수는 아니다:</strong> 브랜딩·이전 자유도 때문에 유리할 수는 있지만, 승인 자체의 필요조건은 아닙니다. 콘텐츠 판정에서 떨어지는데 도메인만 바꾸면 같은 사유로 또 떨어집니다.

도메인을 구매했다면 아래 3가지는 갖춰야 합니다.

1. <strong>DNS CNAME/A 레코드 연동:</strong> 구매한 커스텀 도메인을 GitHub Pages 레포지토리와 CNAME으로 정상 연결해야 합니다.
2. <strong>HTTPS (SSL 보안 프로토콜) 적용:</strong> 보안 연결이 되지 않은 사이트는 심사 대상에서 즉시 제외됩니다. (GitHub Pages는 무료 SSL을 자동 발급해 줍니다.)
3. <strong>구글 애드센스 계정 메타 태그 삽입:</strong> <strong>google-adsense-account</strong> 소유권 확인 태그를 HTML head에 정확히 삽입해야 합니다.

## 🛠️ 3. 승인 통과 4단계 로드맵 (2026년 실전판)

### 1단계: 크롤러 접근 보장 (기술 기반)
* <strong>robots.txt</strong>에서 <strong>Mediapartners-Google</strong> 크롤러를 허용합니다.
* <strong>public/ads.txt</strong>를 게시하고 본인 pub ID와 일치하는지 확인합니다.
* <strong>sitemap.xml</strong>을 제출하고, 깨진 페이지(404)가 색인에 섞여 있지 않은지 확인합니다.
* 정적 빌드(<strong>npm run build</strong>) 결과물에 빈 페이지·깨진 다이어그램이 없는지 직접 엽니다.

### 2단계: 필수 규정 페이지 구축 (Privacy Policy & About)
구글 심사(봇)가 사이트의 정당성을 평가할 때 <strong>개인정보처리방침(Privacy Policy)</strong> 유무를 매우 엄격하게 봅니다.
* 블로그 하단(Footer)에 <strong>/privacy/</strong> 및 <strong>/about/</strong> 페이지 링크를 추가하세요.
* 쿠키 수집 및 제3자 광고(Google AdSense) 관련 안내 문구를 명시해야 합니다.
* About에는 <strong>실명·연락처·운영 이력</strong>을 공개하세요. 익명 필자는 E-E-A-T 감점 요인입니다.

### 3단계: 얇은 글 정리와 롱폼 보강 (가장 중요)
글 3\~5개 상태에서 신청하면 '가치 있는 콘텐츠 없음'으로 거절됩니다. 필자가 실제로 적용한 기준은 아래와 같습니다.

* <strong>900단어 이하 글 전수 조사:</strong> 1,500단어 수준으로 보강하거나 <strong>noindex</strong> 처리합니다. 이 블로그는 구버전 뉴스·구버전 도구글·주제 이탈 글 5편을 색인에서 제외했습니다.
* <strong>noindex仕組み:</strong> 글 frontmatter에 <strong>noindex: true</strong> 한 줄을 넣으면 검색 색인·사이트맵·RSS에서 빠지고 글 자체는 계속 읽을 수 있습니다. 삭제보다 안전한 정리법입니다.
* <strong>1차 경험을 넣는다:</strong> 남의 강연 요약이 아니라 직접 실행한 명령어, 실측 화면, 실제 오류 로그를 넣습니다. 심사자가 "이건 겪어본 사람의 글"이라고 느끼게 만드는 것이 핵심입니다.
* <strong>YMYL 면책:</strong> 주식·법률 글에는 "투자·법률 조언이 아님" 문구를 반드시 넣습니다.

### 4단계: 소유권 태그 삽입 및 재신청 (횟수 관리)
사이트의 head 태그 내부에 구글 애드센스 계정 확인 태그를 추가한 후, 애드센스 콘솔에서 검토를 신청합니다.

```html
<meta name="google-adsense-account" content="ca-pub-9646087317436086" />
```

> ⚠️ <strong>재심사 횟수 제한 주의</strong><br />
> 검토 요청에는 횟수 제한이 있어 다 쓰면 일정 기간 재신청이 막힙니다. <strong>준비 없이 "일단 신청"을 반복하는 것이 최악의 전략</strong>입니다. 3단계까지 끝내고 Search Console에서 색인이 붙는 것을 확인한 뒤에 신청하세요.

## ❓ 4. 자주 묻는 질문 (FAQ)

### Q1. 커스텀 도메인을 연결하면 기존 github.io 주소로 들어오는 방문자는 어떻게 되나요?
GitHub Pages는 기존 <strong>username.github.io</strong>로 들어오는 모든 요청을 새로 설정한 커스텀 도메인으로 <strong>301 리다이렉트(자동 이동)</strong>해 주므로 기존 트래픽 손실 걱정을 하지 않으셔도 됩니다.

### Q2. 심사는 얼마나 걸리나요?
도메인을 정상 연결하고 심사를 제출하면 구글 심사팀 및 봇이 검토를 진행하며, 보통 <strong>수일에서 길게는 2\~4주</strong> 정도 소요됩니다.

### Q3. '가치 없는 콘텐츠' 판정을 받았는데 도메인을 바꿔야 하나요?
아닙니다. 도메인과 무관한 판정이므로 글 정리(보강·noindex·면책)가 먼저입니다. 필자도 소유권은 통과한 상태에서 콘텐츠 판정만 받았고, 도메인이 아닌 글 정리를 처방으로 택했습니다.

### Q4. 재심사 요청 횟수를 다 쓰면 어떻게 되나요?
안내된 날짜까지 대기해야 합니다. 대기 기간을 글 보강에 쓰는 것이 유일한 해법이며, 다음 신청은 한 번에 통과한다는 각오로 준비하세요.

## 📌 5. 총평 및 정리

github.io 블로그의 애드센스 거절은 <strong>도메인 탓으로 돌리기 전에 거절 사유 행을 먼저 읽는 것</strong>에서 시작합니다. 소유권이 통과했는데 콘텐츠 판정에서 떨어졌다면, 살 것은 도메인이 아니라 글 정리입니다.

<strong>크롤러 접근 보장 ➔ 필수 규정 페이지 ➔ 얇은 글 보강·noindex ➔ 횟수 아끼고 재신청</strong>의 순서로 진행하시면, 이 블로그가 지금 밟고 있는 것과 같은 지름길로 가실 수 있을 것입니다.
